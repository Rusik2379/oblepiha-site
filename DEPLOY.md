# Развёртывание на oblepiha-22.ru

Архив содержит сайт, админку, SEO, файл Яндекса и текущие данные из локальной админки в `site-data/`. Пароля и хеша локальной админки в архиве нет. Подходит для Linux VPS с Docker Engine и Docker Compose v2; обычный FTP-хостинг без Node.js/Docker не поддерживает редактор.

## Новый сервер: самостоятельный запуск с HTTPS

1. В DNS создайте записи A для `@` и `www`, указывающие на IPv4 вашего сервера. AAAA добавляйте только при работающем IPv6. Входящие порты 80 и 443 должны быть доступны, а на сервере свободны. Caddy выпустит сертификаты и перенаправит HTTP на HTTPS автоматически.
2. Распакуйте архив на компьютере. Через FileZilla по SFTP загрузите содержимое папки `oblepiha-site` в отдельный каталог на сервере, например `/opt/oblepiha`. Не кладите архив в публичный каталог действующего сайта.
3. Подключитесь к серверу по SSH и перейдите в этот каталог. Создайте боевой пароль и запустите:

   ```sh
   cd /opt/oblepiha
   docker run --rm -v "$PWD:/app" -w /app node:24-alpine node server/setup.mjs
   docker compose -f compose.deploy.yml config --quiet
   docker compose -f compose.deploy.yml up -d
   docker compose -f compose.deploy.yml ps
   ```

4. Откройте `https://oblepiha-22.ru/` и `https://oblepiha-22.ru/editor.html`. Пароль хранится на сервере в `.news-admin-access.txt`. Чтобы прочитать его в своём SSH-терминале:

   ```sh
   cat .news-admin-access.txt
   ```

5. Если сайт не открылся, посмотрите журнал: `docker compose -f compose.deploy.yml logs --tail=80 web site`. Проверьте DNS, порты и настройки имеющегося веб-сервера. Запуск этой конфигурации одновременно с другим сервисом на портах 80/443 невозможен; не останавливайте чужие сайты ради неё.

Требуется установленный Docker: https://docs.docker.com/engine/install/ . На сервере Node.js отдельно ставить не нужно. Если домен меняется, обновите `server/seo.mjs`, `news.js`, `robots.txt` и `Caddyfile`, затем выполните `node tools/update_seo.mjs` (или ту же команду в контейнере Node).

## Если на сервере уже есть HTTPS-прокси

В архиве сохранена прежняя конфигурация `compose.prod.yml` и `nginx.prod.conf` для существующей внешней Docker-сети `proxy-net`. Используйте её вместо самостоятельной конфигурации, когда ваш HTTPS-прокси уже настроен:

```sh
docker run --rm -v "$PWD:/app" -w /app node:24-alpine node server/setup.mjs
docker compose -f compose.prod.yml up -d
```

Привяжите домен к `oblepiha-site:80` в вашем прокси. Эта конфигурация хранит CMS в Docker-томе, а не в `site-data`. При первом переносе локальных данных в **новый пустой** том:

```sh
docker compose -f compose.prod.yml stop oblepiha-news
docker compose -f compose.prod.yml run --rm --no-deps -v "$PWD/site-data:/import:ro" oblepiha-news sh -c 'cp -a /import/. /data/'
docker compose -f compose.prod.yml up -d
```

Не выполняйте импорт поверх существующих боевых публикаций. Подробнее о старой конфигурации — `NEWS-README.md`. Две конфигурации запускайте по отдельности.

## Подтверждение поисковиков

Яндекс: после загрузки проверьте `https://oblepiha-22.ru/yandex_c9a8ccae38e772ef.html`, затем нажмите подтверждение в Яндекс Вебмастере. Содержимое исходного файла сохранено.

Google Search Console: на скриншоте выбран **доменный ресурс**, который подтверждается через DNS. Создайте TXT-запись для корня домена (имя `@`, иногда пустое поле) со значением:

```text
google-site-verification=rxbnlYCCZh1IoC9VWM_ypOfCO0yOa8XkaDgrx06pm_s
```

Сохраните существующие TXT-записи. После применения DNS нажмите «Подтвердить». Загрузка HTML-файла не заменяет DNS-проверку доменного ресурса. Инструкция Google: https://support.google.com/webmasters/answer/9008080?hl=ru .

Добавьте в Google Search Console и Яндекс Вебмастер карту `https://oblepiha-22.ru/sitemap.xml`. Она обновляется при добавлении, редактировании и удалении новостей. Проверьте главную и страницы услуг инструментами проверки URL. Эти действия в аккаунтах и DNS ещё не выполнены автоматически.

## Обновления и резервные копии

Перед обновлением сохраните `site-data/`, `.env.news` и `.news-admin-access.txt` (в режиме старого прокси — также Docker-том `news-data`). При последующих загрузках через FileZilla **не перезаписывайте** боевой `site-data/` данными из исходного архива. Обновляйте код и выполняйте `docker compose -f compose.deploy.yml up -d --force-recreate site`.

Не удаляйте хранилище данных и том Caddy с сертификатами. Папки CMS, файлы с паролями, серверный код и служебные инструменты не выдаются публичным веб-сервером.

Интеграция TravelLine также требует проверки на основном домене: локальный запуск не подтверждает доступность модуля у поставщика.
