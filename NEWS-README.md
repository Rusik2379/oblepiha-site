# Новости и акции

На главной отображаются первые три публикации: сначала закреплённые, затем новые. Все публикации доступны на `/news.html`. Подробные прежние акции сохранены на `/promotions.html`. Дата начала акции с чаем — **1 декабря 2026 года**; она указана и в карточке, и в подробных условиях.

## Редактор

Откройте `/editor.html`. Ссылка на редактор не размещается в навигации. Вход защищён паролем на сервере; знание адреса само по себе не даёт доступа к сохранению или загрузке файлов.

Данные для входа находятся в локальном файле `.news-admin-access.txt`. Этот файл и `.env.news` исключены из Git и не выдаются веб-сервером. Не отправляйте их посетителям сайта.

В редакторе можно создать публикацию с заголовком, текстом и фотографией (JPG, PNG, WebP до 8 МБ), выбрать «Новость» или «Акция», указать дату начала акции, закрепить публикацию, отредактировать или удалить её. Публикация появляется на сайте после сохранения; посетителям с уже открытой страницей нужно обновить страницу. Текст выводится как обычный текст, HTML не выполняется.

## Вакансии

Страница `/vacancies.html` доступна из общего подвала всех публичных страниц. В том же `/editor.html` есть раздел «Вакансии»: название должности и описание обязательны, оплата и график необязательны; контактный телефон используется для кнопки отклика. Можно создавать, редактировать, публиковать, скрывать и удалять вакансии. Скрытые вакансии доступны только после входа в админку и не выдаются публичным API.

Вакансии хранятся в `vacancies.json` в существующем каталоге данных и сохраняются после перезапуска. Файл создаётся пустым при первом запуске обновлённого сервера, новости не перезаписываются. Для резервной копии сохраняйте его вместе с `news.json` и `uploads/`. После обновления серверного кода перезапустите Node.js (или контейнер) и проверьте `/vacancies.html` и раздел вакансий в редакторе. Без API на странице показывается сообщение об ошибке загрузки, а не устаревшие объявления.

## Рекламный баннер

В `/editor.html` есть раздел «Реклама». Загрузите JPG, PNG или WebP до 8 МБ, укажите необязательное название и ссылку по нажатию на картинку, включите «Показывать рекламу на сайте» и сохраните. Можно заменить картинку, отключить показ с сохранением баннера или удалить баннер. Без ссылки картинка не ведёт на другую страницу.

Баннер показывается на любой публичной странице при первом открытии сайта, один раз за сеанс вкладки. Закрывается крестиком, Esc или нажатием на фон. Картинка полностью помещается в экран ПК и телефона. После изменения и сохранения рекламы создаётся новая версия, которую можно увидеть повторно в том же сеансе. В админке реклама не открывается. При недоступности API или картинки показ пропускается, сайт работает дальше.

Настройки хранятся в `advertisement.json` в том же каталоге данных. При первом запуске новая реклама отключена; существующие новости и вакансии сохраняются. Включайте этот файл в резервную копию вместе с остальными данными. Обновление требует перезапуска серверной части.

## Локальный запуск

Требуется Node.js 24. В корне проекта:

```text
node server/setup.mjs
node server/server.mjs
```

Сайт: `http://localhost:8765/`, редактор: `http://localhost:8765/editor.html`. Python `http.server` больше не нужен: он не поддерживает сохранение новостей.

Настройка не заменяет существующий пароль. Для смены выполните `node server/setup.mjs --reset`, затем перезапустите сервер. Новый пароль будет записан в `.news-admin-access.txt`. Пароль не находится в JavaScript браузера; сервер использует scrypt-хеш. Сеансы действуют 8 часов и сбрасываются при перезапуске сервера.

## Боевой сервер

Для нового сервера с доменом `oblepiha-22.ru` подготовлен архив и самостоятельная конфигурация с HTTPS: см. `DEPLOY.md` и `compose.deploy.yml`. Ниже описан прежний вариант с уже существующим HTTPS-прокси.

Изменения подготовлены для существующего `compose.prod.yml`: nginx обслуживает статические файлы, отдельный контейнер Node.js обслуживает `/api/`, `/news-media/`, главную, новости, вакансии и динамическую карту сайта. Публичное содержимое CMS доступно поисковикам сразу в HTML. Редактор требует HTTPS на основном домене: в production используется защищённая HttpOnly-cookie. Порт серверной части не публикуется наружу.

1. Скопируйте обновлённые файлы сайта, каталог `server`, `news-seed.json`, `compose.prod.yml` и `nginx.prod.conf` на сервер.
2. Создайте **отдельный боевой пароль**. В каталоге проекта на Linux-сервере можно выполнить:

   ```sh
   docker run --rm -v "$PWD:/app" -w /app node:24-alpine node server/setup.mjs
   ```

   Либо создайте пароль через Node.js 24 командой `node server/setup.mjs`. `.env.news` должен находиться рядом с `compose.prod.yml`.
3. В существующей сети `proxy-net`, с действующим HTTPS-прокси, запустите:

   ```sh
   docker compose -f compose.prod.yml up -d
   ```

4. Проверьте `/news.html` и `/editor.html` на основном домене.

Это **не было развёрнуто на боевом сервере** автоматически. Обычной загрузки только HTML/CSS недостаточно для редактора. Без API публичные страницы покажут начальные предложения из `news-seed.json`, а редактор сообщит, что сервер не подключён.

## Хранение и резервные копии

Локальные публикации и загруженные фотографии находятся в `.news-data/`. В Docker они хранятся в постоянном томе `news-data`, внутри контейнера — в `/data`. Начальные предложения копируются из `news-seed.json` только при первом запуске с пустым хранилищем. Обновление файлов сайта не перезаписывает существующие новости.

Для резервной копии сохраняйте весь каталог данных: `news.json` и `uploads/`. Не удаляйте Docker-том при обновлении; `docker compose down -v` удалит данные. Фотографии удалённых публикаций сохраняются в хранилище, чтобы случайное удаление публикации не уничтожало сам файл.

## Проверка

```text
node --test server/server.test.mjs
```

Тесты проверяют защиту файлов, пароль, запрет запросов с чужого сайта, CSRF, загрузку фотографий, создание/редактирование/удаление новостей и вакансий, скрытие неопубликованных вакансий, сохранение данных после перезапуска и ограничение попыток входа. Они используют отдельный временный каталог и не меняют данные сайта.
